## What This Project Does

`pdf-ua-fixer` is a Python CLI tool that post-processes PDFs generated by **pdflatex + tagpdf** (TeX Live 2024/2025) to fix PDF/UA-1 accessibility compliance errors. It has been tested on 250+ page documents. XeLaTeX/LuaLaTeX output is not supported.

## Dependencies

```
pip install pikepdf>=10.0 pypdf>=4.0
```

## Commands

**Apply all fixes:**
```
python fix_pdf.py input.pdf                  # produces input_fixed.pdf
python fix_pdf.py input.pdf -o output.pdf    # explicit output path
python fix_pdf.py input.pdf --inplace        # overwrite input
```

**Verify fixes were applied correctly:**
```
python verify_pdf.py input_fixed.pdf
```
A fully-fixed PDF prints three PASS lines. `verify_pdf.py` is also used as the manual regression test — run it before and after any change to a fix module.

## Architecture

Two CLI scripts orchestrate four independent fix modules:

- **`fix_pdf.py`** — opens PDF with pikepdf, runs all four fixes in sequence, saves result
- **`verify_pdf.py`** — opens PDF with pypdf and inspects for three specific conditions

The fix modules live in `fixes/`:

| Module | What it fixes |
|---|---|
| `untagged_paths.py` | Wraps untagged path sequences (booktabs rules, decorative lines) as `/Artifact` so they're invisible to accessibility checkers |
| `th_scope.py` | Adds `/A << /O /Table /Scope /Column >>` directly to TH structure elements; tagpdf stores scope via ClassMap only, which PAC doesn't resolve |
| `artifact_content.py` | Removes `/Artifact` wrappers that contain nested tagged content (a structure violation), re-wrapping only the inner path-drawing sequences |
| `pdfua_metadata.py` | Injects `pdfuaid:part = '1'` into XMP metadata to declare PDF/UA-1 compliance |

**`fixes/utils.py`** provides shared constants and helpers for content-stream parsing:
- `MC_OPEN` / `MC_CLOSE` — marked-content operator sets (BMC/BDC vs EMC)
- `PATH_BUILDERS` / `PATH_PAINTERS` — PDF path operator sets
- `try_resolve()` — safely dereferences pikepdf indirect references
- `operand_bytes()` / `instructions_to_bytes()` — serialize parsed content streams back to bytes

## Key Design Rules

- Fixes only add or adjust accessibility markup; visible content is never changed.
- The tool is **idempotent** — running it twice produces no further changes.
- Each fix module is independent; they do not call each other directly (except `artifact_content.py` reuses path-wrapping logic from `untagged_paths.py`).
- pikepdf is used for all write-path operations (low-level PDF object access); pypdf is only used in `verify_pdf.py` for reading.
